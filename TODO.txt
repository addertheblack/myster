## Red List
# (Named for a literal list of issues written in red pen — circa 2000, shared with a friend
#  as a low-tech issue tracker before the age of ticketing systems.)
- Add authenticated per-block subhash verification to multi-source downloads:
    - Obtain a trustworthy block-hash manifest bound to the requested file hash, so a sender
      cannot choose the expected hash for its own bad block.
    - Verify each block before accepting it or marking it downloaded; associate the block with
      the supplying server's authenticated CID.
    - Reject and re-request bad blocks from another source, and ban the responsible server CID
      from supplying further blocks (define ban scope and persistence when designing this).
    - Keep this separate from download reconnect; hash-to-filename lookup alone does not verify
      the bytes of individual blocks.
- Implement private networks:
    - Find a format for sharing a network file (public key, primary servers, maybe other public keys).
    - Be able to share the network config file (might be similar to network file, or a superset).
    - Explore a type-scoped bootstrap index/rendezvous service for members behind firewalls:
        - Let the bootstrap front authenticated file listings for known servers in that private type.
        - Coordinate a direct transfer where possible, or relay a specific authorized file over
          member-initiated outbound sessions where direct connectivity is unavailable.
        - Bind indexing and transfer requests to the type CID and its membership rules. Do not
          expose arbitrary host/port forwarding or allow the service to proxy unrelated networks.
        - Consider chat and other general-connectivity features separately; their relay and
          presence requirements are broader than the single-type file-sharing case.
- Add reverse connection protocol.
- Pick a default place for downloads in progress (e.g. ~/mysterdata or platform app-data dir on Windows).
- Split off concurrency library from Myster and publish to Maven.
- Make Myster modules compatible.
- Fix naming — probably want to use myster.org and not the current com.myster etc....
- Audit and enforce access controls on all Myster endpoints:
    - Inventory every TCP stream section and UDP transaction; document intentionally public
      operations and the membership/admin permissions required by each protected operation.
    - Check authorization before exposing protected type/file listings, search results, metadata,
      hash lookups, downloads or thumbnails, and before changing protected state.
    - Verify caller identity comes from authenticated transport and review missing checks,
      alternate/batch paths, plaintext requests and fail-open behavior on access-list errors.
    - Verify authorization on every download request, including resumed and partial transfers.
    - Add regression tests proving unauthorized callers cannot read or change protected data,
      while authorized callers and intentionally public operations continue to work.
- Review and implement general server abuse / DoS protection:
    - Harden public-facing TCP handling against automated probes, malformed requests, stalled
      clients, and bots issuing valid Myster requests or repeatedly downloading files.
    - Enforce read deadlines for protocol headers, request bodies, and TLS negotiation so
      incomplete or slow requests cannot occupy connection workers indefinitely.
    - Validate client-supplied string, array, and frame lengths before allocation or processing;
      reject negative, oversized, and truncated payloads.
    - Prevent UDP reflection and packet amplification (don't be a vector for attacks on others).
    - Add general per-IP rate limiting across server requests, beyond invitation password checks.
    - Bound aggregate request rates, concurrent connections, expensive work, and response bandwidth.
    - Limit concurrent connections and downloads both globally and per IP, including repeated
      valid requests that never trigger the unknown-protocol limit.
    - Keep rate-limit tracking bounded and expiring so the defence cannot itself exhaust resources.
- Ensure that the UDP socket can have some sort of Myster global amount of concurrency but if packets arrive too quickly
    then those packets are dropped. This is to prevent a UDP flood from taking down the server. Note
    that the "size" of the concurrent UDP connection should be measured in some k/s of packets per second
    proportional to the k/s that the server can effectively handle.
- Fix DefaultTypeDescriptionList to interact with preferences in a sane way (not using MML).

- Add 3DNS for resolving public keys to hosted ip addresses.
- Fix search-result metadata access: `SearchResult#getMetaData(String)` currently stringifies
  typed `MessagePak` values, forcing column handlers to parse numbers back out for sorting.
  Add a read-only `MessagePak` view/interface for search items so handlers can use typed
  `getLong`, `getString`, `getDate`, etc. without allowing UI code to mutate file stats.
- Optional image-content captions for Pictures: use a local/CLI vision model provider
  (e.g. Ollama, llama.cpp, or a Python Transformers helper) to generate a short
  `/ImageCaption` description. Keep it opt-in, cached under its own metadata schema,
  and privacy-reviewed because captions can expose sensitive image contents.
- Revisit retaining/reusing already-encoded PNG thumbnail bytes to avoid re-encoding:
    - Reuse them only when the image already meets the requested dimensions and protocol
      format/body limits; preserve file-freshness checks and omit local-path cache metadata.
    - Keep encoding the final BufferedImage as the fallback for resized images and providers
      that return bitmap pixels. Deferred beyond the thumbnail protocol milestone.
